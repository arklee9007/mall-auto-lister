# 接入流程

版本：v1.3.0（界面版）。本文与界面里的“接入流程”页内容一致，数据来源是 `adapters/` 里每个适配器的 `REQUIRED_ONBOARDING`、`CONNECTION_SHAPE` 与 `connect()` 定义，以及 `lib/api-client.mjs` 的接口方法定义。

## 先分清两件事

- **咱们这边已就绪**：插件这边已经做好的部分，可以直接用（扫样表、对字段、试跑、看草稿、出文件包、排程模拟）。
- **等第三方开口**：平台／店铺的 API 与授权还没接通。写入口现在调了会明确拒绝，不返回假成功。

申请链接、审批时限、费用以各平台当期口径为准，本文不写；写着“待核实”的就是还没核实到，不要按猜测去办。

凭据口径：所有凭据（AppKey、AppSecret、Token、密钥）只走目标连接配置（`config/targets.json`），永不进代码与报告。`connect()` 只校验连接配置形状，缺必填项直接报错。

接通后通用的六个步骤（所有第三方目标都一样）：

1. 按下面清单完成入驻与商家授权（入驻主体、开放平台应用、Token／密钥）。
2. 凭据填进目标连接配置，不进代码。
3. 调 `connect()` 校验连接配置形状：缺必填项会直接报错，不静默通过。
4. 把 client 的四个方法体换成真实请求：`createProduct`（建商品，只到草稿态）、`getProduct`（读商品状态）、`setShelf`（上架／下架）、`listProducts`（按条件列商品）。方法名与参数不变，不改调用方。
5. `dry-run` 看映射 → `import-fake` 看草稿，确认草稿态正确，再走正式流程。
6. 上下架规则按该平台的 `SHELF` 状态名配 `sellableStates`（可售态才允许动）。

## 自有后台

### 通用商城模板

- **咱们这边已做好的部分**：字段映射与翻译已就绪。`dry-run` 可看每件商品翻译后的 payload（商品名、分类、颜色／尺码／图案三轴、价格分、库存、主图、运费方式与运费说明、SKU 明细）。运费按买家后台已建模板登记填写，不编默认值。
- **商家要准备的东西**：商城须已部署；运费模板、分类须先在商城后台建好，并登记进配置（`freightTemplates`）；价格单位在核对映射时确认为元或分。
- **还缺的第三方开口**：没有第三方开口。缺的是写库层：适配器只出翻译结果 payload，写入商城数据库的步骤待 Sam 中途测试反馈后做终版。接通后：写库层按 payload 字段写入，`dry-run` → `import-fake` 试跑确认草稿态，再按上下架规则配 `sellableStates`。

### WANDER 本店

- **咱们这边已做好的部分**：字段映射与翻译已就绪，与通用模板同一套 payload。差别是本店固定三维（颜色／尺码／图案），三轴皆不可为空。
- **商家要准备的东西**：与通用模板相同。另注意：维度不足时程序以“默认色／均码／默认款”填充并在报告里点名，须人工确认填充是否可接受。
- **还缺的第三方开口**：没有第三方开口。缺的是写库层，与通用模板相同：适配器只出 payload，写入本店数据库的步骤待终版。接通后步骤与通用模板相同。

### 文件版（无后台）

- **咱们这边已做好的部分**：已完全就绪，无需任何接口。`file-pack` 出标准商品表.csv（固定表头，规格展平，扩展字段为 JSON 列）＋图片改名计划.json（`<序号>_<角色>_<原名>`）。上下架不适用。
- **商家要准备的东西**：拿到两个文件后，按自己系统的导入口径手工导入；各平台列名以后台当期模板为准，须按 `dry-run` 的翻译结果逐列核对。
- **还缺的第三方开口**：无。文件版设计上就不接数据库与接口，没有待接通的第三方开口。

## 第三方平台

### 抖音（抖店）

- **咱们这边已做好的部分**：字段映射完整（必填、品类扩展字段、规格维、图片要求、上下架状态名均已按公开资料写死，查不到的标待实测）。接口调用层已定死四个方法：`createProduct`（建商品，只到草稿态）、`getProduct`（读商品状态）、`setShelf`（上架／下架）、`listProducts`（按条件列商品）。上下架状态：上架“售卖中”、下架“已下架”、可售态“售卖中”。API 销售属性最多 3 类，单商品 SKU 上限 300。
- **商家要准备的东西**（`REQUIRED_ONBOARDING`）：
  - 入驻主体：个体工商户或企业营业执照开抖店（个人店限部分类目）；保证金按类目交。由 Sam／买家在抖店后台操作。
  - 开放平台授权：抖店开放平台建应用，商家 OAuth 授权拿 access_token；Token 有有效期，须刷新机制。凭据只进目标连接配置。
  - 先行模板：运费模板、规格模板、品牌模板先在抖店后台建好，工具只填模板名。
  - 类目资质：按品类上传质检报告、商标注册证或商标使用授权书；每次建新商品均须传。
- **连接配置要填的东西**（`connect()` 校验形状）：AppKey（抖店开放平台应用 AppKey，必填）、AppSecret（必填）、accessToken（商家授权后的 access_token，必填）、shopId（抖店店铺 ID，必填）。
- **还缺的第三方开口（以及接通后的步骤）**：缺上面清单里的入驻与授权，抖店开放平台的 API 开口没打开。现在调 `connect()` 会直接报缺连接配置，调四个接口方法会直接抛“接口未接通”，不返回假成功。申请链接、审批时限、费用以抖店当期口径为准，待核实。接通后走文首通用六步。

### 淘宝

- **咱们这边已做好的部分**：字段映射完整（必填、品类扩展字段、规格维、图片要求、上下架状态名均已按公开资料写死，查不到的标待实测）。接口调用层已定死四个方法：`createProduct`、`getProduct`、`setShelf`、`listProducts`（含义同上）。上下架状态：上架“出售中”、下架进“仓库中”、可售态“出售中”。主图 5 张、800x800 与 SKU 上限 80 为多家卖家教程口径（官方未明文，以后台为准）。
- **商家要准备的东西**（`REQUIRED_ONBOARDING`）：
  - 入驻主体：淘宝个人店或企业店（天猫为另一套入驻口径，不在此适配器内）。
  - 开放平台授权：淘宝开放平台（TOP）建应用，商家 OAuth 授权拿 SessionKey；调用须 AppKey＋AppSecret＋SessionKey＋HMAC-SHA256 签名。凭据只进目标连接配置。
  - 先行模板：运费模板与发货地先在千牛后台建好，工具只填模板名。
  - 类目属性：细粒度必填以类目属性表为准，发布前须按类目取属性表核对。
- **连接配置要填的东西**：AppKey（淘宝开放平台应用 AppKey，必填）、AppSecret（必填）、SessionKey（商家 OAuth 授权后的 SessionKey，必填）、shopNick（淘宝店铺昵称，用于核对授权店铺，必填）。
- **还缺的第三方开口（以及接通后的步骤）**：缺上面清单里的入驻与授权，TOP 的 API 开口没打开。现在调 `connect()` 与四个接口方法均明确拒绝。申请链接、审批时限、费用以淘宝开放平台当期口径为准，待核实。接通后走文首通用六步。

### 小红书

- **咱们这边已做好的部分**：字段映射完整（必填、品类扩展字段、规格维、图片要求、上下架状态名均已按公开资料写死，规格维上限与 SKU 上限未查到公开资料，标待实测、不编造）。接口调用层已定死四个方法：`createProduct`、`getProduct`、`setShelf`、`listProducts`（含义同上）。上下架状态：上架“售卖中”、下架“已下架”、可售态“售卖中”；另有审核态“待审核／审核中／审核不通过”。
- **商家要准备的东西**（`REQUIRED_ONBOARDING`）：
  - 入驻主体：企业店或个体店主体资质；个人开发者基本拿不到开放平台权限，须认证服务商或企业主体。
  - 开放平台授权：小红书电商开放平台应用＋商家 OAuth 授权，权限范围含商品／订单／库存／售后。凭据只进目标连接配置。
  - 品牌授权：品牌商品须品牌方正规授权文件（2026 新规：全球购美妆个护采销凭证不再认可），无合规授权新品直接驳回。
  - 类目资质：按类目备齐资质（如食品经营许可证）；食品须标签实拍图。
- **连接配置要填的东西**：AppKey（小红书电商开放平台应用 AppKey，必填）、AppSecret（必填）、accessToken（商家授权后的 access_token，必填）、shopId（小红书店铺 ID，必填）。
- **还缺的第三方开口（以及接通后的步骤）**：缺上面清单里的入驻与授权，小红书电商开放平台的 API 开口没打开。现在调 `connect()` 与四个接口方法均明确拒绝。申请链接、审批时限、费用以小红书当期口径为准，待核实。接通后走文首通用六步。

## 自建店

### Shopify

- **咱们这边已做好的部分**：字段映射完整（按 Shopify 商品 CSV 公开列名翻译：Title 为新商品唯一必填；多规格／更新时须 URL handle；规格选项上限 3，单商品最多 2048 个组合、250 张图、CSV 上限 15MB）。接口调用层已定死四个方法：`createProduct`、`getProduct`、`setShelf`、`listProducts`（含义同上）。上下架状态：上架 active、下架 draft、可售态 active。运费：Shopify 商品本身无运费模板字段，运费在后台 Shipping and delivery 按区域与费率设置，适配器把运费映射写进备注。
- **商家要准备的东西**（`REQUIRED_ONBOARDING`）：
  - 店铺订阅：Shopify 按月订阅，付费后才可上架售卖。
  - API 授权：后台建自定义应用或走 OAuth，拿 Admin API access_token。凭据只进目标连接配置。
  - 配送设置：后台 Settings → Shipping and delivery 建好配送区域与费率。
  - 图片地址：CSV 导入用图片 URL（Image Src 列），须先把图传到可公开访问的地址或 Shopify Files。
- **连接配置要填的东西**：shop（Shopify 店铺域名，如 xxx.myshopify.com，必填）、accessToken（自定义应用或 OAuth 的 Admin API access_token，必填）、apiVersion（Admin API 版本，如 2026-01，选填）。
- **还缺的第三方开口（以及接通后的步骤）**：缺上面清单里的店铺订阅与 API 授权，Admin API 开口没打开。现在调 `connect()` 与四个接口方法均明确拒绝。订阅费用、申请链接以 Shopify 当期口径为准，待核实。接通后走文首通用六步。另：不等 API 也能先用手工路径——按 `dry-run` 的翻译结果在后台手工建商品，或按 Shopify 商品 CSV 列名手工整理导入（导入只到草稿：Published 列填 FALSE，对应 draft；上架须在后台改 active）。

### WooCommerce

- **咱们这边已做好的部分**：字段映射完整（按 WooCommerce 内置导入 CSV 公开列名翻译：Name 为唯一必填；Type 非简单商品时必填；SKU 强烈建议，更新去重靠它；Published 列 1 上架／0 草稿；图片用完整 URL）。接口调用层已定死四个方法：`createProduct`、`getProduct`、`setShelf`、`listProducts`（含义同上）。上下架状态：上架 publish、下架 draft、可售态 publish。运费：按配送区域＋运费方式在后台设置；商品可指定 Shipping class（运费等级），适配器把固定运费／模板名写入备注。
- **商家要准备的东西**（`REQUIRED_ONBOARDING`）：
  - 站点：自有 WordPress 站点＋ WooCommerce 插件（主机与域名费用另计）。
  - API 密钥：WooCommerce 后台 REST API 建密钥（Consumer Key／Secret）。凭据只进目标连接配置。
  - 配送设置：配送区域与运费方式（统一费率／按重量等）、Shipping class（运费等级）先在后台建好。
  - 图片地址：导入用完整图片 URL，须先把图传到可公开访问的地址。
- **连接配置要填的东西**：siteUrl（WordPress 站点地址，必填）、consumerKey（WooCommerce REST API Consumer Key，必填）、consumerSecret（WooCommerce REST API Consumer Secret，必填）。
- **还缺的第三方开口（以及接通后的步骤）**：缺上面清单里的站点与 API 密钥，REST API 开口没打开。现在调 `connect()` 与四个接口方法均明确拒绝。主机与域名费用另计，金额待核实。接通后走文首通用六步。另：不等 API 也能先用手工路径——按 `dry-run` 的翻译结果在后台手工建商品，或按 WooCommerce 内置导入 CSV 列名手工整理导入（导入只到草稿：Published 列填 0）。

### 有赞微商城

- **咱们这边已做好的部分**：字段映射完整（按有赞官方文章的发布与批量导入口径翻译：发布页必填为商品名称、商品图、价格、库存；批量导入走后台 商品中心 → 商品库 → 商品导入 → 下载模板，须用当期模板，旧模板不建议沿用）。接口调用层已定死四个方法：`createProduct`、`getProduct`、`setShelf`、`listProducts`（含义同上）。上下架状态：上架“已上架”、下架“已下架”、可售态“已上架”。注意三段状态：已导入商品库 ≠ 已发布到店铺 ≠ 已上架可售，导入只到商品库。
- **商家要准备的东西**（`REQUIRED_ONBOARDING`）：

- **连接配置要填的东西**：AppKey（有赞云开放平台应用 AppKey，必填）、AppSecret（必填）、accessToken（商家授权后的 access_token，必填）、shopId（有赞店铺 ID，必填）。
- **还缺的第三方开口（以及接通后的步骤）**：缺上面清单里的店铺与开放平台授权，有赞云的 API 开口没打开。现在调 `connect()` 与四个接口方法均明确拒绝。套餐费用以有赞当期口径为准，待核实。接通后走文首通用六步。另：不等 API 也能先用手工路径——批量导入直接用后台模板（以后台当期下载的为准），导入只到商品库，再在后台发布、上架。

### SHOPLINE

- **咱们这边已做好的部分**：字段映射完整（按 SHOPLINE 商品文件公开口径翻译：必填为 Product Handle、Product Name、Images；建议填 Price、Quantity、Categories；规格选项支持 Option1–5，本插件引擎上限 3 维，4–5 维商品须拆包或走定制适配；商品文件为 CSV 或 XLSX、上限 40MB，模板含两行表头须保留；多规格每组合一行，Title 只填首行）。接口调用层已定死四个方法：`createProduct`、`getProduct`、`setShelf`、`listProducts`（含义同上）。上下架状态：上架 Activated、下架 Deactivated、可售态 Activated。运费：Package（包裹）信息目前不支持商品 CSV 导入导出，运费在后台物流设置，固定运费／模板名写入备注。
- **商家要准备的东西**（`REQUIRED_ONBOARDING`）：
  - 店铺订阅：SHOPLINE 店铺订阅（版本与费用按当期套餐）。
  - 开放平台授权：SHOPLINE 开放平台建应用，商家 OAuth 授权；批量导入也可不走 API，直接用后台商品文件。凭据只进目标连接配置。
  - 先行设置：分类与供应商须先在后台建好（批量导入不能新建分类与供应商）；后台物流设置须建好。
  - 导入模板：以后台下载的商品模板为准（两行表头都保留，列名与顺序不改），文件上限 40MB。
- **连接配置要填的东西**：shop（SHOPLINE 店铺域名，必填）、AppKey（SHOPLINE 开放平台应用 AppKey，必填）、AppSecret（必填）、accessToken（商家授权后的 access_token，必填）。
- **还缺的第三方开口（以及接通后的步骤）**：缺上面清单里的店铺订阅与开放平台授权，SHOPLINE 开放平台的 API 开口没打开。现在调 `connect()` 与四个接口方法均明确拒绝。订阅费用以 SHOPLINE 当期口径为准，待核实。接通后走文首通用六步。另：不等 API 也能先用手工路径——批量导入直接用后台商品文件（以后台下载的模板为准，两行表头保留），导入只到下架草稿：Status 填 Deactivated、Visibility 填 Hidden；上架须在后台改 Activated。
