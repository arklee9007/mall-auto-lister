# 中途测试步骤（Sam 动手版）

目标：你亲手走一遍「导入对方模板 → 核对映射 → 拖包 → 看草稿 → 上下架计划」，确认流程顺不顺、报告看不看得懂。全部在测试文件上跑，不碰真实店铺与数据库。

## 准备

测试包位置：generic-automation-addon/sam-test/。里面有：对方商城样表.csv（模拟别人家商城导出的表，表头叫法不一样）、material-pack/（测试素材包：清单.csv + images/ 图片）、上下架状态.json、上下架规则.json、上下架规则-可读时间.json。命令在 generic-automation-addon 目录下跑。

测试包怎么到你电脑上：Cooper 发你的是整个 generic-automation-addon 文件夹（压缩包或 git archive），解压到哪个盘都行，下面命令里的路径以你解压的位置为准。进去之后先自查 Node 是否装好：

```
node --version
```

能打出 v20.19 或更高的版本号就是装好了；打不出或版本低于 v20.19，先装 Node 再继续。

下面命令分 Windows 与 macOS/Linux 两栏写，你用哪台电脑就看哪一栏。Windows 上在 PowerShell 里跑，输出路径用 `$env:TEMP\我的文件包`；macOS/Linux 用 `/tmp/我的文件包`。

## 步骤

1. 扫描对方模板：
   ```
   node bin/addon.mjs scan sam-test/other-shop/对方商城样表.csv
   ```
   预期：程序认出 产品名称→商品名、类别→分类、单价→价格、库存→库存、图片→主图、邮费方式→运费方式；颜色/尺寸提议为规格维；保质期/净含量提议为扩展字段；缺失必填映射为无。
   注意：输出里 description/subtitle/keywords 显示 missing 是正常的——那三个是可选字段（描述、副标题、关键词），样表里本来就没有，不是缺必填。缺失必填映射那一行显示“无”就对了。
2. 生成映射配置：
   ```
   node bin/addon.mjs init-profile 测试店 sam-test/other-shop/对方商城样表.csv --target generic-template
   ```
   预期：生成 profiles/测试店.json。打开看一遍：映射对不对、有没有张冠李戴。不对的地方直接改这个 JSON 文件里的 source，改完保存就是「核对一次保存复用」。
   另注意：--target 只认 generic-template、wander、file-only、douyin、taobao、xiaohongshu、shopify、woocommerce、youzan、shopline 十个，写别的会在这一步就直接拒绝，不会等到后面才报错。
3. 试跑素材包：
   ```
   node bin/addon.mjs dry-run 测试店 sam-test/material-pack/清单.csv --images sam-test/material-pack/images
   ```
   预期：3 件商品，0 错误；手工香皂有 3 条适配提醒（扩展字段无处写、说明图并入详情图）；首件翻译结果里纯棉T恤为 白/黑 × M/L 共 4 个 SKU，各 15 件；试跑结论明确写「未写入任何目标」。
   首行会写「提醒共 N 条（解析提醒 X 条，适配提醒 Y 条）」，两类分开数、总数对得上才是对的。
   报告里还会有一节「运费映射」，逐件写清包邮 / 固定运费 / 运费模板名与计费价格；运费格留空会直接报错（工具不自动编默认模板，须先在买家后台建好模板再填名）。
4. 模拟导入看草稿：
   ```
   node bin/addon.mjs import-fake 测试店 sam-test/material-pack/清单.csv --images sam-test/material-pack/images
   ```
   预期：草稿 0 → 3 件，全部 stage=pool、review=pending、onShelf=false（草稿态，不直接上架）。
5. 文件版：
   Windows：
   ```
   node bin/addon.mjs file-pack 测试店 sam-test/material-pack/清单.csv --images sam-test/material-pack/images --out $env:TEMP\我的文件包
   ```
   macOS/Linux：
   ```
   node bin/addon.mjs file-pack 测试店 sam-test/material-pack/清单.csv --images sam-test/material-pack/images --out /tmp/我的文件包
   ```
   预期：输出目录里有 标准商品表.csv（3 行，价格已是分，规格展平，扩展字段为 JSON 列）与 图片改名计划.json。
6. 上下架计划与回滚：
   ```
   node bin/addon.mjs schedule-demo 测试店 sam-test/上下架状态.json sam-test/上下架规则-可读时间.json --now 2026-11-20T10:00
   ```
   预期：执行前 p1:false p2:false p3:true；执行后 p1:true（到时上架）p2:false（还在池里，未达可售状态被跳过）p3:false（售罄自动下架）；回滚后与执行前一致，显示「回滚一致：是」。
   说明：规则文件现在可以用可读时间写（shelfAt: "2026-11-14T13:20"，就是北京时间墙上时间），不用再填一长串毫秒数；老的毫秒写法（shelfAtUtcMs）也还认，两者结果一样。sam-test/上下架规则.json 就是老写法那份，留着对照。
7. 边界试手（可选）：
   - 把清单里某件商品的价格删空再 dry-run，预期报错并拒绝导入。跑完把价格改回去（改回 79.9 / 39 / 25.5 原值），再跑一次 dry-run 确认回到 0 错误。
     ```
     node bin/addon.mjs dry-run 测试店 sam-test/material-pack/清单.csv --images sam-test/material-pack/images
     ```
   - 把配置里 schedule.pollMinutes 改成 1 再跑任意一条命令（比如 dry-run），预期被配置校验拒绝（exit 2，提示轮询间隔不得小于 5 分钟）。跑完把 pollMinutes 改回 5，再跑一次 dry-run 确认通过。
   - 把样表另存为 .xlsx 再 scan，预期直接拒绝并提示换 CSV/JSON。

## 新：自己生成专用模板（不用对方的表头也能走）

如果你有自己的商城网站、自己的分类，不用等别人给你样表，自己生成一套模板：

```
node bin/addon.mjs generate-template sam-test/other-shop/对方商城样表.csv --out $env:TEMP\我的模板.json --name 我的美妆模板 --target generic-template
```

预期：生成一个 JSON 模板草稿（上面命令是 Windows PowerShell 写法；macOS/Linux 把 `$env:TEMP\我的模板.json` 换成 `/tmp/我的模板.json`）。打开它（记事本就行），按文件顶部的 howToEdit 改：fields 里每行的 sourceColumn 改成你表里的列名；categories 改成你的分类；specDims 改维名与取值；freightTemplates 改成你后台已建好的运费模板（模板名、计费方式、区域与价格）。没有样表时也可以直接给字段名：

```
node bin/addon.mjs generate-template --fields "商品名,分类,价格,库存,主图,运费方式,颜色" --out $env:TEMP\我的模板.json --name 我的模板 --target generic-template
```

改完保存，再用它建配置、试跑（--template 就是导入时指定这套模板）：

```
node bin/addon.mjs init-profile 我的店 --from-template $env:TEMP\我的模板.json --target generic-template
node bin/addon.mjs dry-run 我的店 sam-test/material-pack/清单.csv --images sam-test/material-pack/images --template $env:TEMP\我的模板.json
```

预期：配置正常生成；试跑 0 错误，报告里有「运费映射」一节。详细的一步一步说明见《个人专用模板设置方法-20261119.md》。
